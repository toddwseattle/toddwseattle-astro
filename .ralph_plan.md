### Task 2: Improve Date Type Safety

**Priority**: MEDIUM
**Complexity**: Medium
**Risk**: Low (dates still work as strings, this adds parsing)

#### 2.1 Convert String Dates to `z.coerce.date()`

**Rationale**:

- Current: `date: z.string()` loses type information
- Better: `date: z.coerce.date()` provides Date object with type safety
- Allows date comparisons, sorting, formatting without manual parsing

**Collections Using Date Fields**:

| Collection         | Fields                 | Impact            |
| ------------------ | ---------------------- | ----------------- |
| `blog`             | `date`                 | ~30-50 posts      |
| `teaching`         | `date`                 | ~2-5 courses      |
| `course-materials` | `date`                 | ~5-10 materials   |
| `experiences`      | `startDate`, `endDate` | ~5-10 experiences |
| `nonprofit`        | `startDate`, `endDate` | ~3-5 entries      |
| `education`        | `startDate`, `endDate` | ~2-3 entries      |

**Implementation Steps**:

1. **Update Schema** (`src/content/config.ts`):

   ```typescript
   const blog = defineCollection({
     type: "content",
     schema: ({ image }) =>
       z.object({
         // ... other fields
         date: z.coerce.date(), // Changed from z.string()
         // ... rest
       }),
   });

   const experiences = defineCollection({
     type: "content",
     schema: z.object({
       // ... other fields
       startDate: z.coerce.date(),
       endDate: z.coerce.date().optional(),
     }),
   });
   ```

2. **Update Components**:

   ```typescript
   // Before (manual parsing needed)
   const dateObj = new Date(post.data.date);

   // After (already a Date object)
   const dateObj = post.data.date; // Type: Date
   ```

3. **Verify Date Formatting**:
   - Check `src/components/blog/BlogCard.astro`
   - Check `src/components/blog/WritingList.astro`
   - Check `src/components/Experience.astro`
   - Update any date formatting logic to use Date methods

**Type Safety Benefits**:

- ✅ Date operations type-checked at compile time
- ✅ No manual parsing needed in components
- ✅ Invalid date formats caught at build time
- ✅ Easier date comparisons for sorting/filtering

**Validation**:

- Content files don't change (Zod coerces strings to dates)
- Frontmatter keeps same format: `date: 2025-01-15`
- Components get Date objects instead of strings

```typescript
const blog = defineCollection({
  type: "content",
  schema: ({ image }) =>
    z.object({
      /** Post title (required, displayed in listings and SEO) */
      title: z.string(),

      /** Short description for SEO and previews (required) */
      description: z.string(),

      /** Publication date (required, used for sorting) */
      date: z.coerce.date(),

      /** Optional hero image (optimized at build time) */
      cover: image().optional(),

      /** Category for grouping posts (deprecated in favor of tags) */
      category: z
        .enum([
          "innovation",
          "software-engineering",
          "teaching",
          "automotive-software",
          "cycling",
          "music",
        ])
        .optional(),

      /** Tags for discovery (preferred over category) */
      tags: z.array(z.string()).optional(),

      /** Featured posts appear on homepage (default: false) */
      featured: z.boolean().optional(),

      /** Draft posts excluded from production (default: true) */
      published: z.boolean().default(true),
    }),
});
```

**Benefits**:

### Task 4: Create TypeScript Type Helpers

**Priority**: LOW
**Complexity**: Low
**Risk**: None (additive only)

#### 4.1 Add Type Utilities for Content Collections

**File**: `src/lib/content-types.ts` (new file)

**Implementation**:

```typescript
import type { CollectionEntry } from "astro:content";

/** Type-safe helper for blog posts */
export type BlogPost = CollectionEntry<"blog">;

/** Type-safe helper for teaching content */
export type TeachingCourse = CollectionEntry<"teaching">;

/** Type-safe helper for course materials */
export type CourseMaterial = CollectionEntry<"course-materials">;

/** Type-safe helper for experiences */
export type Experience = CollectionEntry<"experiences">;

/** Helper to extract data from collection entry */
export type EntryData<T extends CollectionEntry<any>> = T["data"];

/** Helper to check if post has cover image */
export function hasCoverImage(
  post: BlogPost | TeachingCourse | CourseMaterial,
): post is BlogPost & { data: { cover: ImageMetadata } } {
  return post.data.cover !== undefined;
}

/** Helper to format date consistently */
export function formatDate(date: Date, locale = "en-US"): string {
  return new Intl.DateTimeFormat(locale, {
    year: "numeric",
    month: "long",
    day: "numeric",
  }).format(date);
}

/** Helper to sort posts by date (newest first) */
export function sortByDate<T extends { data: { date: Date } }>(
  posts: T[],
): T[] {
  return posts.sort((a, b) => b.data.date.getTime() - a.data.date.getTime());
}
```

**Usage in Components**:

```astro
---
import { getCollection } from "astro:content";
import type { BlogPost } from "../lib/content-types";
import { sortByDate, formatDate } from "../lib/content-types";

const posts = await getCollection("blog");
const sortedPosts = sortByDate(posts);
---

{sortedPosts.map((post: BlogPost) => (
  <article>
    <h2>{post.data.title}</h2>
    <time>{formatDate(post.data.date)}</time>
  </article>
))}
```

**Benefits**:

- ✅ Type aliases reduce verbosity
- ✅ Type guards provide runtime safety
- ✅ Utility functions centralize common logic
- ✅ Easier to refactor in future

### Content Collections

```typescript

  schema: ({ image }) =>
    z.object({
      cover: image().optional(), // ← Type-safe image handling
      date: z.coerce.date(), // ← Type-safe date handling
    }),
});
```

### Image Optimization

✅ **Always import images, never use string paths**

```astro
---
import { Image } from "astro:assets";
import heroImg from "../assets/images/hero.jpg";
---
<Image src={heroImg} alt="Hero" />
```

### Type Inference

✅ **Let TypeScript infer collection types**

```typescript
const posts = await getCollection("blog");
// posts is typed as CollectionEntry<'blog'>[]
```

---
