# Ralph Plan: Blog & Homepage Polish

## Objectives

- Reduce hero image sizes in blog posts to improve layout density.
- Personalize the home page with an author photo.

## Technical Constraints

- Use **Astro Image component** for optimization.
- Hero images should be constrained to **50% of parent width**.
- Author image should be stored in `src/assets/` and referenced via ESM import.

## Architecture Analysis

### Current Structure

**Blog Post Layout** (`src/pages/writing/[slug].astro`):

- Lines 72-84: Hero image (`cover`) currently renders at full width (100%)
- Uses `<Image>` from `astro:assets` (✓ correct)
- Image dimensions: 1200x675 with `aspect-video` wrapper
- Currently: `class="w-full h-full object-cover"`

**Homepage** (`src/pages/index.astro`):

- Uses `<HeroBanner />` component (lines 31)
- HeroBanner component fetches from `hero` content collection
- No author photo currently displayed
- Logical insertion point: After HeroBanner or within "Mini bio" section (lines 103-111)

**Resume Page** (`src/pages/resume/index.astro`):

- Line 10: `title = 'Resume'`
- Needs to be: `title = 'Todd Warren - Resume'` for SEO

**Available Assets**:

- `src/assets/images/profile.jpg` (exists ✓)
- `src/assets/images/profile_oblong.jpg` (exists ✓)

### TypeScript Safety

**Content Collection Schema** (`src/content/config.ts`):

- Blog schema (lines 3-25): `cover: image().optional()` (correctly typed)
- Hero schema (lines 125-135): No image field currently
- All schemas use Zod for runtime validation (✓)

**Type Imports**:

- Blog posts use: `import type { CollectionEntry } from 'astro:content'` (✓ correct)
- Image imports should use: `import { Image } from 'astro:assets'` (✓ already correct)

## Astro-Specific Considerations

### Image Optimization

- `<Image>` component generates multiple sizes automatically
- Lazy loading handled by Astro (except `loading="eager"`)
- Imports from `src/assets/` are optimized at build time
- Remote images require different handling (not applicable here)

### TypeScript Integration

- `.astro` files support TypeScript in frontmatter
- Image imports are typed as `ImageMetadata`
- Content collections enforce schema with Zod
- `astro check` validates all types

### Islands Architecture

- All changes are static (no `client:*` directives needed)
- Header/Footer use `client:load` (existing pattern)
- No new JavaScript shipped to client

### Build-Time Safety

- Image references validated at build time
- Missing images cause build failure (desired)
- Content collection schema errors caught early
- TypeScript errors prevent deployment
